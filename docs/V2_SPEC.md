## 1. Цели и не-цели

**Цели**

- Убрать из кода жёсткую привязку к «Миша/Настя», спискам `CARDS` и `CATEGORIES` из `.env`, валюте `AMD`.
- Ввести группы, карты с собственной валютой и права доступа к картам.
- Заменить синхронизацию с Excel скачиваемым отчётом.

**Не-цели v2**

- Публичная регистрация (приложение остаётся закрытым, группы создаёт только администратор).
- Несколько групп у одного пользователя.
- Офлайн-режим, платежи, импорт банковских выписок.
- Переписывание аналитики: она получает только фильтр по доступным картам и валюту отчётности.

## 2. Принятые решения

| Вопрос | Решение |
|---|---|
| Итоги по группе при разных валютах карт | Одна **валюта отчётности группы** (задаёт owner) |
| Пользователи и группы | Приглашение по ссылке; **один пользователь состоит ровно в одной группе** |
| Привязка и скрытие карт | Привязка карты к пользователю = доступ; скрытая карта **не видна нигде** |
| Уровни доступа к карте | `view` (смотреть) и `edit` (добавлять траты) |
| Кто правит и удаляет существующие траты | **Только owner** группы; он видит все карты |
| Валюта траты | Как сейчас: сумму можно ввести в другой валюте (например, в евро), она пересчитывается по курсу **на момент ввода** (курс можно поправить вручную) |
| Категории | **Своя настройка на группу**, управляет owner |
| Удаление карты | **Только архив**: карта с тратами не удаляется |
| Часовой пояс и валюта отчётности | **Одни на группу** |
| Кто создаёт группы | **Только администратор приложения** (пользователь Миша); в приложении появляется отдельная роль «администратор» |
| Excel-синхронизация | Код остаётся, помечается **deprecated**, выключена по умолчанию; вместо неё скачиваемый отчёт |

## 2.1. Принцип простоты интерфейса

**Для обычного пользователя (member) приложение выглядит и работает как сейчас.** Вся новая сложность (группы, карты, доступ,
приглашения, валюты отчётности) живёт только на страницах «Группа» и «Администрирование», которых обычный пользователь не видит.

- Форма траты, «Анализ» и «Операции» остаются теми же. Никаких новых обязательных полей, экранов и настроек.
- Если у пользователя одна доступная карта, поле «Карта» в форме не показывается, карта подставляется сама. Если несколько, как сейчас: список.
- Выбор валюты в форме и переключатель валюты на странице анализа остаются, как сейчас. Если у группы одна валюта, лишнего не появляется.
- Страница «Группа» видна только owner, «Администрирование» только администратору; в меню у остальных этих пунктов нет.
- Скрытые карты, чужие группы и недоступные действия не показываются вовсе (а не «серыми»). Без сообщений об ограничениях и пустых состояний, которые бы объясняли устройство системы.
- Любое новое решение проверяется вопросом: «заметит ли обычный пользователь изменение?». Если да, нужен веский повод.

## 3. Роли и права

Две независимые роли:

**Администратор приложения** (системная роль, пользователь Миша)

- Создаёт группы, назначает owner (создаёт ему приглашение), отключает группы и пользователей, сбрасывает пароли.
- **Не получает доступ к тратам чужих групп**: управление и данные разделены. Свои траты Миша видит как owner своей группы.

**Роль в группе**

| Роль | Что может |
|---|---|
| `owner` | Видит все карты и траты группы. Добавляет, **правит и удаляет** любые траты. Управляет участниками, приглашениями, картами, категориями, валютой отчётности, доступом к картам. Не может удалить себя; есть передача владения |
| `member` | Видит только карты, которые ему даны. `view` — смотрит траты, итоги и графики по этим картам. `edit` — дополнительно **добавляет** траты по карте. Править и удалять существующие траты не может |

Правила видимости:

- Карта без записи доступа для пользователя **скрыта**: её нет в форме, в «Операциях», в фильтрах, графиках, итогах, подсказках названий и отчёте Excel.
- Фильтрация выполняется **в SQL** по списку доступных `card_id`, а не в интерфейсе.
- Эта модель заменяет прежние `EDITOR_USERS` (теперь только выбирает владельцев первой группы при первом старте), `canEdit` и `can_edit_override` (колонка удалена миграцией 0015).

## 4. Модель данных

| Сущность | Поля (суть) |
|---|---|
| `groups` | id, название, валюта отчётности, часовой пояс, `disabled_at` |
| `users` | как сейчас (логин, пароль, имя) + флаг администратора приложения |
| `memberships` | `user_id` (**уникален**: одна группа на пользователя), `group_id`, роль `owner` / `member` |
| `invitations` | `group_id`, роль, хеш токена (открытым не хранится), срок 7 дней, одноразовая, кем создана, статус |
| `cards` | id, `group_id`, название, **валюта карты**, `archived_at` |
| `card_access` | `card_id`, `user_id`, уровень `view` / `edit`; нет записи = карта скрыта |
| `categories` | `group_id`, название, порядок, `archived_at` |
| `expenses` | к текущим полям добавляются `group_id`, `card_id`; сумма и валюта карты; введённая сумма, её валюта и курс (если вводили в другой валюте); сумма в валюте отчётности и курс на момент траты |

Дополнительно:

- Суммы хранятся целыми в **минорных единицах** (`bigint`) с учётом числа знаков валюты. Сейчас это `int4` в драммах, потолок 2,1 млрд.
- Любой запрос к данным обязан фильтровать по `group_id` из членства пользователя. Доступ по одному `id` записи без проверки группы запрещён.
- Старые поля (`card` как текст, `excel_snapshot` и др.) остаются для deprecated-синхронизации.

## 5. Валюты

- У каждой карты есть своя валюта.
- Трата вводится как сейчас: пользователь выбирает валюту суммы (из разрешённых в настройках) и при необходимости правит курс. Сумма пересчитывается в валюту карты по курсу на момент ввода (источник: ЦБ Армении). Введённая сумма, валюта и курс сохраняются в записи.
- Группа имеет одну **валюту отчётности** (задаёт owner). Графики, итоги, сравнение месяцев и отчёт Excel считаются в ней. Переключатель показа в другой валюте (как на странице анализа сейчас) остаётся.
- Курс на момент траты сохраняется в записи и не пересчитывается задним числом.
- Смена валюты отчётности — отдельная операция owner с подтверждением и пересчётом по сохранённым курсам (см. риск R1).

## 6. Приглашения и учётные записи

1. Администратор создаёт группу и приглашение для её owner.
2. Owner создаёт приглашения для участников (роль, срок 7 дней, один раз).
3. Приглашённый открывает ссылку, сам задаёт логин и пароль.
4. Owner может отозвать приглашение, отключить участника (его прошлые траты остаются, автор сохраняется) и сбросить ему пароль.
5. Пользователи и пароли из `.env` (`AUTH_USERS`, `AUTH_PASSWORD_*`) заменяются записями в БД; в `.env` остаётся только начальная настройка администратора.

## 7. Интерфейс

- Страница **«Группа»** (только owner): участники и приглашения, карты (создать, переименовать, валюта, архив, матрица доступа), категории, валюта отчётности.
- Страница **«Администрирование»** (только администратор приложения): список групп, создание группы и приглашения owner, отключение, сброс пароля.
- Форма расхода: показывает только карты, где у пользователя `edit`; категории группы.
- «Анализ» и «Операции» автоматически видят только доступные карты; фильтр «Карта» перечисляет только их. Кнопки правки и удаления только у owner.
- Кнопка **«Скачать Excel»** на вкладке «Операции» (см. п. 8).
- Тексты интерфейса остаются русскими.
- Для member интерфейс не усложняется (см. п. 2.1).

## 8. Excel: отчёт и deprecated-синхронизация

**Отчёт** (`GET /api/.../export.xlsx`)

- Учитывает текущие фильтры (период, категории, карты и т.д.) и **права доступа** пользователя.
- Листы: «Операции» (дата, карта, категория, название, сумма в валюте карты, сумма в валюте отчётности, курс, автор), «По месяцам», «По категориям».
- Файл создаётся заново, а не правится: нет проблем с чужими данными в книге.
- Текст записывается как значения, не формулы (защита от formula injection). Есть лимит на число строк и таймаут.
- Имя файла: `расходы-ГГГГ-ММ-ДД.xlsx`.

**Синхронизация с Excel**

- Код и тесты остаются, помечаются как **deprecated** (комментарии, README, docs).
- Выключена по умолчанию; включается флагом конфигурации и только для одной группы (вашей) с текущим файлом.
- Новые возможности (карты, валюты, доступ) в неё **не добавляются**.
- Бэкап БД покрывает её данные, как сейчас.

## 9. Миграция существующих данных

Одна миграция на сервере; перед ней обязательны бэкап БД и пробное восстановление (`scripts/backup-db.sh`, `scripts/verify-backup.sh`).

1. Создать группу «Семья» (валюта отчётности AMD, часовой пояс как сейчас): Миша — owner и администратор приложения, Настя — member.
2. Создать карты «Миша» и «Настя» (валюта AMD). Насте дать доступ `edit` к обеим, как сейчас (если не нужно иначе).
3. Перенести `CATEGORIES` из `.env` в таблицу категорий группы.
4. Проставить `group_id` и `card_id` существующим записям (по названию карты).
5. Перевести суммы в минорные единицы (для AMD ×1) и записать курс 1 к валюте отчётности.

Миграции остаются forward-only. Откат: восстановление из бэкапа.

## 10. Безопасность и тесты

- **Изоляция групп**: тесты, что пользователь одной группы не видит и не меняет данные другой (аналитика, операции, отчёт, подсказки, обращение по `id`).
- **Матрица доступа**: скрытая карта не попадает ни в один агрегат; `view` не может добавлять; `member` не может править и удалять.
- **Приглашения**: токен хранится хешем, срок, одноразовость, защита от перебора, лимит на создание.
- **Роли**: администратор не получает данные чужих групп; owner не может удалить себя и последнего owner.
- Тесты PGlite, как сейчас; перед деплоем — полный прогон и пробное восстановление бэкапа.

## 12. Риски и допущения

- **R1. Исторические курсы.** ЦБ Армении отдаёт текущие курсы. Поэтому курс сохраняется в каждой трате, а смена валюты отчётности пересчитывает по сохранённым курсам. Валюты, которых нет у ЦБ, в v2 не поддерживаются.
- **R2. Объём изменений.** Изоляция групп затрагивает почти все запросы и репозитории; это самая рискованная часть, отсюда отдельный этап 2 с тестами.
- **R3. Закрытое приложение.** Без самостоятельной регистрации новые группы создаются только вручную администратором.
- **Допущение A.** Фразу «сумма в евро с курсом на текущий момент» понимаю как сохранение текущего поведения: вводится сумма в выбранной валюте, курс подставляется текущий и редактируется, пересчёт идёт в валюту карты. Если имелось в виду другое, поправьте.
- **Допущение B.** Уровень `edit` означает «добавлять траты»; правка и удаление существующих только у owner (по вашему ответу).
- **Допущение C.** Администратор приложения не видит чужие траты; управление группами и данные разделены. Если нужно иначе, скажите.
