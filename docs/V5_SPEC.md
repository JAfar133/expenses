# ТЗ v5: API для интеграций, шаблоны, Telegram, товары из чеков

Статус: **проект**, реализация не начата. Документ на русском, как и остальные в `docs/`.
Основа: v4 ([V4_SPEC.md](V4_SPEC.md)), группы и роли из [V2_SPEC.md](V2_SPEC.md).

## 1. Цели и принципы

- Приложением можно пользоваться не только из браузера: стабильный API с токенами для Home Assistant и скриптов.
- Частые траты добавляются одним касанием, **без перегрузки формы «Добавить»**.
- Приложение само сообщает о важном (лимиты, сбои) в Telegram.
- Позиции чеков складываются в общие «товары», чтобы по ним можно было считать аналитику.
- Обычный участник не видит новых сложных настроек, всё необязательное спрятано. Правила из `CLAUDE.md` действуют как раньше.

Этапы выкладываются по отдельности, каждый полезен сам по себе (порядок в разделе 7).

## 2. Решения владельца

| Вопрос                | Решение                                                                                       |
| --------------------- | --------------------------------------------------------------------------------------------- |
| Telegram              | Один бот на установку                                                                         |

## 3. API и токены доступа (этап 1)

**Токены.** Личные, у каждого имя, область (`read` или `write`), срок (необязательно), можно отозвать.

- Формат `et_` + 32 случайных байта в base64url. Показывается **один раз** при создании. В базе только SHA-256, префикс (первые 8 знаков) для опознания и `last_used_at`.
- Передаётся заголовком `Authorization: Bearer …`, никогда в URL. Не попадает в логи.
- Токен действует от имени владельца и **не шире его прав** (группа, доступ к картам, роль). Область `read` не пишет.
- Токены создаются и отзываются только из сессии с cookie (токеном токен не выпустить). Сброс пароля отзывает все токены пользователя.
- Ограничение частоты запросов по токену. Неверный токен логируется без значения.

**Стабильный публичный слой `/api/v1`.** Внутренние маршруты `/api/*` остаются как есть и могут меняться, публичные описаны в OpenAPI (`GET /api/v1/openapi.json`) и меняются только с новой версией.

| Метод и путь                       | Что делает                                                                      | Область |
| ---------------------------------- | ------------------------------------------------------------------------------- | ------- |
| `GET /api/v1/summary?period=month` | Потрачено, число операций, расход в день, остаток по лимитам, в валюте на выбор | read    |
| `GET /api/v1/budgets`              | Лимиты по категориям: потрачено, лимит, остаток, процент                        | read    |
| `GET /api/v1/expenses?limit=`      | Последние операции                                                              | read    |
| `POST /api/v1/expenses`            | Добавить расход (с ключом идемпотентности)                                      | write   |
| `GET /api/v1/templates`            | Доступные пользователю шаблоны                                                  | read    |
| `POST /api/v1/templates/:id/apply` | Создать расход по шаблону (необязательно: `amount`, `date`)                     | write   |

**Интерфейс.** Настройки → «Доступ по API»: список токенов (имя, префикс, область, последний вызов), «Создать токен» (показать один раз с кнопкой «Копировать»), «Отозвать». Блок виден всем, но свёрнут; обычному участнику ничего лишнего не показывается.

**Документация.** `docs/HOME_ASSISTANT.md`: готовые примеры `rest` sensor (за месяц, остаток по категории) и `rest_command` (добавить расход, применить шаблон) для `configuration.yaml`.

## 4. Шаблоны быстрых действий (этап 2)

**Шаблон:** название кнопки, категория, карта (необязательно: тогда «моя карта по умолчанию»), название расхода, сумма и валюта (необязательно). Область: **личный** или **групповой**.

- Групповой шаблон создаёт владелец группы **или** пользователь делится своим личным (владелец может убрать любой групповой). Каждый пользователь **скрывает** групповые шаблоны: по одному или все сразу (личная настройка). Скрытие не влияет на других.
- Если у пользователя нет права добавлять на карту из шаблона, берётся его карта по умолчанию.
- Таблицы: `expense_templates` (группа, владелец, область, поля, порядок, архив), `template_hidden` (пользователь, шаблон); «скрыть все групповые» это предпочтение `templates.hideGroup`.

**Как не перегрузить форму.** В поля формы ничего не добавляется. Идея:

1. **Вход.** Один значок «⚡» в строке заголовка формы «Добавить». Он **виден только если у пользователя есть доступные шаблоны**, иначе его нет совсем. Нажатие открывает нижнюю панель со списком шаблонов (название, категория, сумма).
2. **Нажатие на шаблон.** Если сумма указана: расход создаётся сразу, показывается уведомление «Добавлено · Отменить» (отмена мягко удаляет). Если суммы нет: форма открывается уже заполненной, остаётся ввести сумму.
3. **Создание.** Не отдельной формой на главном экране: пункт «Сохранить как шаблон» в меню «⋯» операции в списке и кнопка в уведомлении после сохранения расхода («Сохранить как шаблон»). Управление (переименовать, скрыть, поделиться, удалить, порядок) в Настройки → «Шаблоны».
4. Шаблоны доступны через API (раздел 3), поэтому кнопка Home Assistant вызывает тот же шаблон.

## 5. Telegram (этап 3 уведомления, этап 4 мониторинг)

**Бот.** Один на установку. Токен бота и id чата администратора для мониторинга лежат в серверном `.env` (`TELEGRAM_BOT_TOKEN`, `TELEGRAM_ADMIN_CHAT_ID`; единственный источник, чтобы внешний скрипт мониторинга работал и при упавшем приложении; права файла 600, значения не печатаются и не логируются). Вход приложения в Telegram: длинный опрос (`getUpdates`), входящий порт не нужен.

**Привязка.** Настройки → «Уведомления в Telegram»: «Привязать» выдаёт одноразовый код (живёт 10 минут, хранится хешем), пользователь отправляет боту `/start КОД`, чат привязывается к его учётной записи. «Отвязать» и «Отправить тест». Блок виден, только если бот включён администратором.

**События (у каждого пользователя свои переключатели).**

| Событие                                          | Кому                                                        |
| ------------------------------------------------ | ----------------------------------------------------------- |
| Лимит категории или общий: 80% и 100%            | владелец группы и по желанию любой участник по своим картам |
| Дневной лимит ИИ почти исчерпан / ошибки ИИ      | администратор                                               |
| Приложение недоступно, мало места, бэкап устарел | администратор (этап 4)                                      |

- Лимит: **одно сообщение на порог за период** (`notification_log`: ключ события, период), без повторов; пересчёт после правок и удалений не шлёт заново.
- Сообщения короткие, на русском, со ссылкой на нужную страницу.

**Мониторинг (этап 4).** Скрипт `scripts/watchdog.sh` по cron на сервере каждые 5 минут проверяет `/api/ready`, место на диске, возраст последнего бэкапа (БД и чеков) и шлёт сообщение напрямую в Telegram. Одно сообщение при поломке и одно при восстановлении, без спама. Не зависит от приложения.

## 6. Товары из чеков (этап 5)

**Проблема.** «Молоко 3,2%», «MILK Parmalat 1L», «Կաթ» это один товар.

**Решение (пробуем, качество проверяем на реальных чеках).**

- В позиции новое поле `product` (общее название, строчными) и `product_source` (`ai`/`manual`). Исходное название с чека остаётся как есть.
- **Нормализация при разборе чека.** В тот же запрос к модели добавляется поле `product` для каждой позиции. В промпт передаётся список уже существующих товаров группы (самые частые, не больше 200), и модель **переиспользует** их, а новое название придумывает, только если ничего не подходит. Дополнительного вызова модели нет.
- **Ручная правка.** В позиции можно изменить товар. Исправление запоминается как `product_aliases` (название с чека → товар) и применяется к следующим позициям с таким же названием без модели.
- **Управление.** Список товаров группы с числом позиций: переименовать, **слить несколько в один**. Видно только владельцу группы.
- **Аналитика.** Вкладка «Товары»: топ товаров по сумме и количеству, динамика цены за единицу (по `price / quantity`), по периоду и карте с обычными фильтрами. Позиции без товара показываются как «Без товара» (ручные позиции, чеки до этапа).
- Старые чеки можно обработать пакетно одним действием администратора (расходует лимит ИИ, делается по желанию).
- Риск: качество нормализации зависит от реальных чеков, поэтому этап последний и начинается после проверки Gemini.

## 8. Открытые вопросы

- Шаблон с суммой создаёт расход сразу (с отменой). Достаточно ли «отмены» или нужен предварительный показ?
- Нужны ли токены только для чтения для отдельных карт (сейчас токен наследует всё, что видит пользователь)?
- Уведомления о лимитах получает только владелец или каждый участник по своим картам (в проекте: по выбору каждого)?
