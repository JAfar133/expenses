# Expenses Tracker

Веб-приложение для совместного учёта расходов. Операции вносятся через форму и сохраняются в
**PostgreSQL**, а существующий Excel на личном OneDrive поддерживается как зеркало: приложение пишет
в оба хранилища, при недоступном Excel ставит запись в очередь, а раз в несколько минут (и по кнопке)
подтягивает в базу строки, добавленные в Excel вручную. **Excel необязателен**: если путь к файлу не задан,
приложение работает только с базой.

| Папка / файл                   | Что внутри                                                  |
| ------------------------------ | ----------------------------------------------------------- |
| [`backend/`](backend)          | Fastify API, PostgreSQL, синхронизация с Excel, OneDrive    |
| [`frontend/`](frontend)        | React-форма добавления расхода и панель синхронизации (PWA) |
| `docker-compose.yml`, `infra/` | PostgreSQL, pgAdmin, backend и web (Caddy) в Docker         |
| `scripts/`                     | Скрипты запуска и восстановления из резервной копии         |

## Статус

MVP v0.1, в работе. Готово: запись в PostgreSQL и в Excel, очередь при открытом Excel, синхронизация
по таймеру и кнопке, OneDrive через rclone, форма, защита от дублей, резервные копии, Docker Compose.
Вход по логину и паролю (пользователи Миша и Настя, сессия на сутки с обновлением до недели) тоже готов. Ещё не сделано: история и аналитика.

Как это устроено в двух словах (вход, запись расхода, синхронизация, выкладка): [docs/PIPELINE.md](docs/PIPELINE.md).

## Быстрый старт для разработки (Mac)

Нужны Node.js 22+, Docker Desktop и настроенный rclone с remote `onedrive` (см. [backend/README.md](backend/README.md)).

```bash
./scripts/start-all.sh        # PostgreSQL + backend + frontend, остановка: Ctrl+C
```

Откройте http://127.0.0.1:5173. Frontend сам проксирует `/api` на backend (`http://127.0.0.1:3000`).

**Вход.** Приложение открывается формой входа: логин `misha` или `nastya`. Пароли для разработки скрипт создаёт сам при первом запуске, показывает их
и сохраняет в `backend/.env` (`AUTH_PASSWORD_MISHA`, `AUTH_PASSWORD_NASTYA`); их можно заменить своими (не короче 8 символов) и перезапустить backend.
После входа в форме по умолчанию выбрана карта пользователя.

Скрипт при необходимости сам поставит зависимости, создаст `backend/.env` из `.env.example`, поднимет
PostgreSQL в Docker (порт **5433**, чтобы не мешать вашим другим базам на 5432), проверит, что rclone видит
файл в OneDrive и что порты свободны. Логи backend и frontend идут в один терминал с префиксами.

| Скрипт                      | Что делает                                              |
| --------------------------- | ------------------------------------------------------- |
| `scripts/start-all.sh`      | Запускает PostgreSQL, backend и frontend                |
| `scripts/start-backend.sh`  | Только PostgreSQL и backend                              |
| `scripts/start-frontend.sh` | Только frontend                                         |
| `scripts/restore-backup.sh` | Возвращает Excel из резервной копии (`--list` — список) |
| `scripts/deploy.sh`         | На сервере: обновляет код и перезапускает приложение    |

Чтобы открыть приложение с телефона в той же Wi-Fi сети, передайте `--host`:
`./scripts/start-all.sh --host`, затем откройте `http://<IP-вашего-Mac>:5173`.

Если скрипт не запускается («permission denied»): `chmod +x scripts/*.sh`.

## Запуск в Docker Compose

Поднимает всё сразу: PostgreSQL, pgAdmin, backend и web (Caddy раздаёт интерфейс и проксирует `/api`).

> Полный пошаговый гайд по серверу (подготовка, rclone, `.env`, доступ без домена, переезд на домен, бэкапы,
> обслуживание, неполадки): **[docs/DEPLOY.md](docs/DEPLOY.md)**. Ниже краткая версия.

```bash
cp .env.example .env                 # задайте пароли базы, pgAdmin и пользователей (openssl rand -base64 18) и путь к Excel
mkdir -p secrets && chmod 700 secrets
cp ~/.config/rclone/rclone.conf secrets/rclone.conf && chmod 644 secrets/rclone.conf
#   без Excel: touch secrets/rclone.conf (пустой файл) и не задавайте ONEDRIVE_FILE_PATH в .env
docker compose up -d --build
```

| Сервис     | Адрес                     | Примечание                                                                                                                                                                  |
| ---------- | ------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Приложение | http://127.0.0.1:8080     | Порт `HTTP_PORT`                                                                                                                                                            |
| pgAdmin    | http://127.0.0.1:5051     | Вход: `PGADMIN_EMAIL` / `PGADMIN_PASSWORD`. При первом открытии введите пароль базы (`POSTGRES_PASSWORD`). Подключение «Expenses Tracker» уже настроено. Порт `PGADMIN_PORT` |
| PostgreSQL | 127.0.0.1:5433            | Порт `POSTGRES_PORT`, наружу не открыт                                                                                                                                      |
| backend    | только внутри сети Docker | Наружу отдельным портом не публикуется                                                                                                                                      |

Что важно знать:

- Все порты слушают только `127.0.0.1`. **Пока в приложении нет авторизации, не открывайте их в сеть**
  (`WEB_BIND=0.0.0.0` только вместе с публичным режимом ниже). pgAdmin даёт полный доступ к базе: смените пароль в `.env`.
- Конфигурация rclone копируется в том `backend-data` при первом запуске: токены OneDrive обновляются
  внутри тома. Чтобы подставить новый `rclone.conf`, удалите `rclone/rclone.conf` в этом томе.
- Данные живут в томах: `pgdata` (база), `backend-data` (rclone и резервные копии), `pgadmin-data`.
  `docker compose down` их сохраняет, `docker compose down -v` **удаляет вместе с базой**.
- Контейнеры перезапускаются сами (`restart: unless-stopped`), в том числе после перезагрузки сервера.
- Только база и pgAdmin для разработки: `docker compose up -d --wait postgres pgadmin`.
- HTTPS: укажите домен в `SITE_ADDRESS` (например, `expenses.example.com`), Caddy получит сертификат сам.
  Для этого нужны открытые порты 80/443 и DNS, но сначала нужна авторизация.
- Если порт занят другим проектом, задайте другой в `.env` (`HTTP_PORT`, `PGADMIN_PORT`, `POSTGRES_PORT`).

## Публичный доступ без домена

По умолчанию все порты слушают только `127.0.0.1`. Если нужно открыть приложение из интернета, подключите `docker-compose.public.yml`: он открывает
порты 80/443 и включает HTTPS. Сайт защищает **вход в самом приложении** (логин и пароль пользователей), отдельного пароля Caddy на сайте нет.
PostgreSQL остаётся доступен только на localhost сервера, а pgAdmin открывается отдельным адресом через тот же Caddy под паролем Caddy.

Домен не нужен: возьмите бесплатный адрес из IP сервера с дефисами, например `1-2-3-4.nip.io` (или `1.2.3.4.sslip.io`). Caddy сам получит для него
сертификат Let's Encrypt, для этого порты 80 и 443 должны быть открыты в файрволе провайдера и не заняты другими сервисами.

```bash
# 1. Хеш пароля Caddy для pgAdmin (пароль вводится в запросе и не остаётся в истории команд); длинный случайный: openssl rand -base64 18
docker run --rm -it expenses-tracker-web caddy hash-password

# 2. В .env (хеш ОБЯЗАТЕЛЬНО в одинарных кавычках, в нём есть символы $):
#    AUTH_PASSWORD_MISHA=...  AUTH_PASSWORD_NASTYA=...                  # пароли входа в приложение, не короче 8 символов
#    SITE_ADDRESS=1-2-3-4.nip.io
#    PGADMIN_ADDRESS=pgadmin.1-2-3-4.nip.io
#    PGADMIN_BASIC_AUTH_USER=admin
#    PGADMIN_BASIC_AUTH_HASH='$2a$14$...'
#    COMPOSE_FILE=docker-compose.yml:docker-compose.public.yml     # чтобы обычный `docker compose up -d` подключал оба файла

# 3. Запуск
docker compose up -d
docker compose logs web | grep -iE "certificate|obtained|error"
```

Вход: пароль вводится один раз, затем приложение остаётся открытым: access-токен действует 24 часа и сам обновляется по refresh-токену до 7 дней
(не дольше 30 дней с ввода пароля). Подробности о токенах, защите от подбора и смене пароля: [backend/README.md](backend/README.md#вход-в-приложение),
[docs/DEPLOY.md](docs/DEPLOY.md#51-пользователи-и-пароли).

pgAdmin: HTTPS, пароль Caddy (Basic Auth), затем вход в сам pgAdmin. Для просмотра записей лучше подключаться пользователем базы только для чтения: см.
[docs/DEPLOY.md](docs/DEPLOY.md#87-pgadmin-из-интернета-чтобы-смотреть-записи). Если нужен простой HTTP без сертификата, задайте `SITE_ADDRESS=:80`,
но тогда пароль при входе уходит по сети открытым текстом.

## Что делает синхронизация

Подробности и схема — в [backend/README.md](backend/README.md#как-работает-хранение).

- Расход сохраняется в PostgreSQL и сразу пробуется в Excel. Если файл открыт в Excel (на любом
  устройстве), расход ждёт в очереди и дописывается сам, когда файл освободится.
- Раз в 5 минут и по кнопке «Синхронизировать» новые строки из Excel попадают в базу. Одинаковые
  расходы не склеиваются.
- Удаление и правка строк в Excel переносятся в базу как **мягкое удаление**: запись помечается удалённой, но не стирается и
  её можно вернуть. Если пропало слишком много записей сразу (например, Excel подменён пустым файлом), удаление не применяется,
  а значок синхронизации предупреждает.

## Ограничения MVP

- Нужен доступ к OneDrive для записи в Excel; при его недоступности расходы копятся в очереди.
- Пользователи заданы списком в настройках (Миша и Настя), регистрации нет. Пароли лежат в `.env` открытым текстом, в базе только хеши.
- Офлайн-режима нет.
