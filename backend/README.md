# Backend

Node.js + TypeScript + Fastify. Принимает расходы и дописывает их в таблицу `Операции`
файла Excel на OneDrive.

## Требования

- Node.js 22.13+ (нужен встроенный `node:sqlite`; при запуске Node может напечатать `ExperimentalWarning: SQLite` — это нормально)
- [rclone](https://rclone.org/) с настроенным remote для личного OneDrive

## Настройка rclone

```bash
rclone config                 # создайте remote типа onedrive (personal), имя: onedrive
rclone lsl "onedrive:Документы/Расходы-dev.xlsx"   # проверка доступа к файлу
```

Файл конфигурации rclone содержит OAuth-токены: не добавляйте его в Git.

## Запуск

```bash
npm install
cp .env.example .env
npm run dev        # с перезапуском при изменениях
npm start          # обычный запуск
```

Сервер слушает `HOST:PORT` (по умолчанию `127.0.0.1:3000`).

| Переменная           | По умолчанию                   | Описание                                              |
| -------------------- | ------------------------------ | ----------------------------------------------------- |
| `NODE_ENV`           | `development`                  | Окружение                                             |
| `HOST`, `PORT`       | `127.0.0.1`, `3000`            | Адрес сервера                                         |

| `RCLONE_CONFIG`      | стандартный путь rclone        | Путь к `rclone.conf`                                  |
| `BACKUP_DIR`         | `./backups`                    | Папка резервных копий Excel                           |
| `BACKUP_RETENTION_DAYS` | `30`                        | Сколько дней хранить копии и ключи идемпотентности    |
| `SQLITE_PATH`        | `./data/app.sqlite`            | Техническая SQLite-база (идемпотентность)             |
| `RCLONE_MODE`        | `daemon`                       | `daemon` — постоянный процесс rclone (быстро), `cli` — запуск на каждую команду |

| `CARDS`              | `Миша,Настя`                   | Список карт через запятую                             |
| `CATEGORIES`         | `кафе,одежда,продукты,…`       | Начальные категории; к ним добавляются значения из Excel |

Значения по умолчанию для `ONEDRIVE_FILE_PATH` нет специально: так приложение не запишет
данные в рабочий файл случайно. Для разработки используйте `Расходы-dev.xlsx`.

## API

Префикс `/api`, формат JSON.

| Метод и путь          | Назначение                                                    |
| --------------------- | ------------------------------------------------------------- |
| `GET /api/health`     | Проверка работы, OneDrive не трогает                          |
| `GET /api/config`     | Валюта                                                        |
| `GET /api/cards`      | Список карт                                                   |
| `GET /api/categories` | Категории: конфигурация + значения из Excel (кеш 5 минут)     |
| `POST /api/expenses`  | Добавить расход (нужен заголовок `Idempotency-Key`)           |

Пример:

```bash
curl -X POST localhost:3000/api/expenses -H 'content-type: application/json' \
  -H "Idempotency-Key: $(uuidgen)" \
  -d '{"date":"2026-10-10","card":"Миша","category":"кафе","name":"Кофе","amount":1650}'
```

Успех — `201` (при повторе с тем же ключом — `200` и прежний результат), `{ "success": true, "data": { "id": "…", … }, "message": "Расход успешно добавлен" }`.
Ошибка — `{ "success": false, "error": { "code": "…", "message": "…" } }`.

| Статус | Код                      | Когда                                                              |
| ------ | ------------------------ | ------------------------------------------------------------------ |
| 400    | `BAD_REQUEST`            | Битый JSON                                                         |
| 400    | `IDEMPOTENCY_KEY_REQUIRED`, `INVALID_IDEMPOTENCY_KEY` | Нет заголовка `Idempotency-Key` или он неверного формата |
| 409    | `CONFLICT`               | Файл на OneDrive изменился во время записи; расход не добавлен     |
| 409    | `REQUEST_IN_PROGRESS`    | Запрос с этим ключом ещё выполняется                               |
| 422    | `INVALID_DATE`, `INVALID_CARD`, `INVALID_CATEGORY`, `INVALID_NAME`, `INVALID_AMOUNT` | Ошибка валидации |
| 422    | `IDEMPOTENCY_KEY_REUSED` | Ключ уже использован для другого расхода                           |
| 423    | `FILE_LOCKED`            | Файл открыт в Excel и заблокирован; расход не добавлен             |
| 503    | `STORAGE_UNAVAILABLE`    | OneDrive недоступен или нет доступа; расход не добавлен            |
| 500    | `WRITE_STATUS_UNKNOWN`   | Неизвестно, записан ли расход. **Не повторяйте автоматически**, сначала проверьте таблицу |
| 500    | `BACKUP_FAILED`          | Не удалось сделать резервную копию; файл не менялся                |
| 500    | `INTERNAL_ERROR`         | Внутренняя ошибка                                                  |

Каждый ответ содержит заголовок `X-Request-Id` — тот же `requestId` стоит во всех строках лога запроса.

## Как устроена запись

1. Валидация данных, затем блокировка записи (одновременно идёт только одна запись).
2. Скачивание свежей копии файла во временный каталог. Версия копии — хеш её содержимого
   (`quickxor`), посчитанный по скачанным байтам.
3. Резервная копия скачанного файла (если её сделать не удалось, запись отменяется).
4. Правка XML листа и таблицы: расход ставится в первую свободную строку внутри таблицы,
   при необходимости диапазон таблицы расширяется. Остальные части файла (графики, формулы,
   стили) не меняются.
5. Повторное открытие результата и проверка новой строки.
6. Проверка, что хеш файла на OneDrive всё ещё равен версии скачанной копии (иначе `409`),
   загрузка и сверка хеша загруженного файла с локальным.
7. Удаление временных файлов.

Почему не ExcelJS: при пересохранении он теряет графики и динамические массивы из вашего файла,
поэтому для записи используется точечная правка XML (`src/services/excel/`). ExcelJS нужен только
для чтения и проверки.

Между проверкой версии и загрузкой остаётся небольшое окно гонки. Строгой защиты от параллельного
ручного редактирования в MVP нет. Пока файл открыт в Excel (например, на Mac через Excel для
OneDrive), OneDrive блокирует запись и API отвечает `423 FILE_LOCKED`.

### Режимы rclone и скорость

Каждый запуск rclone к OneDrive делает около шести последовательных HTTP-запросов, поэтому
отдельная команда занимает 4–5 секунд. Поэтому по умолчанию backend держит один постоянный
процесс `rclone rcd` (`RCLONE_MODE=daemon`), который переиспользует соединения:

| Режим    | Полная запись (замер, Армения → OneDrive) |
| -------- | ----------------------------------------- |
| `daemon` | 5–7 секунд                                |
| `cli`    | 20–30 секунд (бывают выбросы до 45 с)     |

Как работает режим `daemon`:

- backend сам запускает `rclone rcd` и прогревает соединение при старте (около 2–7 секунд),
  а при остановке завершает его;
- процесс слушает только `127.0.0.1` на случайном порту, логин и пароль генерируются при каждом
  запуске и передаются через переменные окружения (в списке процессов не видны);
- если процесс упал, следующий запрос запускает его заново;
- если backend убит жёстко (`kill -9`), `rclone rcd` может остаться работать до перезагрузки;
  найти и остановить: `pkill -f "rclone rcd"`;
- если запрос завершился по таймауту, операция внутри rclone может ещё доработать до конца,
  поэтому для записи это считается результатом «неизвестно» (`WRITE_STATUS_UNKNOWN`).

## Резервные копии

Перед каждой записью скачанный файл сохраняется в `BACKUP_DIR`:

```
backups/2026-10-10/expenses-20-15-32-a1b2c3.xlsx    # дата и время — по APP_TIMEZONE
```

- копии доступны только владельцу (папки `0700`, файлы `0600`) и не отдаются веб-сервером;
- при запуске и раз в сутки копии старше `BACKUP_RETENTION_DAYS` дней удаляются;
- копии лежат на том же диске, что и backend. Для надёжности периодически копируйте папку
  `backups/` в другое место.

### Восстановление из копии

```bash
./scripts/restore-backup.sh --list                      # какие копии есть
./scripts/restore-backup.sh backend/backups/2026-10-10/expenses-20-15-32-a1b2c3.xlsx
```

Скрипт проверяет, что копия — целая книга Excel, просит подтверждение (`yes`), сохраняет текущую
версию в `backups/before-restore/` (чтобы восстановление можно было отменить), загружает копию
в OneDrive и сверяет хеш. Перед запуском закройте файл в Excel, иначе OneDrive вернёт `423`.
Вернуть копию вручную без скрипта можно и через `rclone copyto <копия> onedrive:<путь к файлу>`.

Также у файла есть история версий OneDrive (Excel или веб-интерфейс → «Журнал версий»).

## Защита от дублей (Idempotency-Key)

`POST /api/expenses` требует заголовок `Idempotency-Key` (UUID). Статус каждого ключа хранится в SQLite:

| Ситуация                                              | Ответ                                                       |
| ----------------------------------------------------- | ----------------------------------------------------------- |
| Новый ключ                                            | Запись, `201`                                               |
| Тот же ключ после успеха                              | `200`, прежний результат (тот же `id`), записи нет          |
| Тот же ключ, пока первый запрос выполняется           | `409 REQUEST_IN_PROGRESS`                                   |
| Тот же ключ с другими данными                         | `422 IDEMPOTENCY_KEY_REUSED`                                |
| Тот же ключ после явной ошибки (`409`, `423`, `503`)  | Новая попытка разрешена: файл точно не менялся              |
| Тот же ключ после `WRITE_STATUS_UNKNOWN`              | Снова `WRITE_STATUS_UNKNOWN`, запись не повторяется         |

Если backend перезапустили во время записи, такая операция помечается как неизвестная
(`WRITE_STATUS_UNKNOWN`) и не повторяется. Frontend после `WRITE_STATUS_UNKNOWN` берёт новый ключ:
пользователя просят сначала проверить таблицу, а повторная отправка — его осознанное решение.

Гарантия «ровно одна запись» действует в рамках одного экземпляра backend.

## Логи

JSON-логи в stdout. На каждую операцию — строка с `requestId`, пользователем, длительностью и
результатом:

```json
{"requestId":"fa412ab2","operation":"expense.storage","downloadMs":2090,"backupMs":2,"excelMs":99,"uploadMs":2393,"totalMs":4585,"msg":"Expense written to Excel"}
{"requestId":"fa412ab2","operation":"expense.create","userId":"local","durationMs":4590,"result":"success","replayed":false,"msg":"Operation completed"}
```

Данные расхода (наименование, сумма), пароли и токены в лог не попадают; заголовки `Authorization`
и `Cookie` скрываются.

## Структура

```
src/
  app.ts, server.ts           сборка Fastify и запуск
  config/env.ts               переменные окружения
  modules/expenses/           маршруты, схема валидации, бизнес-логика
  storage/                    ExpenseRepository и реализация для Excel
  services/excel/             правка и чтение XLSX
  services/onedrive/          клиенты rclone (daemon и CLI), коды ошибок
  infrastructure/             очередь записи, резервные копии, идемпотентность, SQLite
  errors/                     ошибки с HTTP-статусами
tests/{unit,integration,fixtures}
```

## Тесты

```bash
npm test                         # без обращения к OneDrive
npm run typecheck
RUN_ONEDRIVE_TESTS=1 npm test    # + живые тесты с настоящим OneDrive (оба режима rclone, около 1,5 минуты)
```

Живые тесты работают с отдельным файлом `Документы/expenses-tracker-test.xlsx` и удаляют его в конце;
рабочие файлы не затрагиваются.

Для интеграционных тестов нужна копия вашего Excel: `tests/fixtures/expenses-dev.xlsx`.
Файл содержит ваши данные и исключён из Git, поэтому после клонирования скачайте его сами:

```bash
mkdir -p tests/fixtures
rclone copyto "onedrive:Документы/Расходы-dev.xlsx" tests/fixtures/expenses-dev.xlsx
```
